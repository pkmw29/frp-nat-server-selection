## 为什么内网穿透只要一台低配公网服务器

frp 干的事情很单一：把公网服务器当跳板，把外部请求转进没有公网 IP 的内网机器。公网那台跑服务端 frps，内网那台跑客户端 frpc，frpc 主动往外连，形成一条隧道，外部访问公网服务器的指定端口，流量顺着隧道落到内网服务上。

整条链路里，frps 只做转发，CPU 和内存几乎不构成瓶颈，真正吃紧的是带宽。1 核 1G 跑一个家庭场景的穿透，资源上没有任何压力。前排那些教程把重点放在“怎么配”，很少讲这台机器该买多大、花多少钱，其实答案很直接：最小的那一档就够。

新版 frp 用 toml，旧教程里的 ini 写法属于旧格式，字段名在后来的版本里改过，照抄老文章容易卡在启动这一步。

服务端配置，公网机器上：

toml
# frps.toml
bindPort = 7000
auth.token = "一串足够长的随机字符"


客户端配置，内网机器上：

toml
# frpc.toml
serverAddr = "你的服务器公网IP"
serverPort = 7000
auth.token = "与服务端完全一致"

[[proxies]]
name = "web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 80
remotePort = 8080


`bindPort` 是 frpc 连 frps 用的端口，`remotePort` 是映射到公网、给外部访问的端口，两个不是一回事，防火墙里都要放行。配好之后，外部访问 `服务器公网IP:8080`，请求就落到了内网机器的 80 端口。想用域名加 HTTPS，可以在服务器上用 Caddy 反代到 `remotePort`，证书交给 Caddy 统一申请续期，内网服务不用装证书。

除了 TCP，frp 还支持 UDP、HTTP、HTTPS，以及不直接暴露端口的 STCP 和 SUDP。远程桌面走 3389、SSH 走 22、NAS 管理页走 5000、MQTT 走 1883，都是同一套配置换个端口号。

## 搭建时最容易翻车的四件事

**一、两端 token 不一致。** 服务端写了一个，客户端复制时漏了字符，或者客户端压根没填，现象是 frpc 一直重连、日志刷错误。排查动作：把两边的 `auth.token` 贴到同一个文本编辑器里逐字符比对，别看屏幕。

**二、端口只放通了一个。** `bindPort` 放通了，`remotePort` 忘了加，结果是 frpc 显示连接成功，外部却打不开。云厂商的安全组和系统自带防火墙是两套规则，两边都要放。端口没放通是内网穿透连不通最常见的原因，比配置写错更常见。

**三、两端时间差超过 15 分钟。** 这一条很多人不知道。frp 做认证时校时，服务端和客户端时间偏差过大会直接连接失败，报错信息还不太直观。服务器上跑 `timedatectl` 看一眼，把 NTP 同步打开基本就解决了。旧配置里的 `authentication_timeout = 0` 是关掉时间校验，能用但不建议，等于放弃了一层保护。

**四、把管理页面裸奔在公网。** 穿透打通之后，内网的 NAS 后台、路由器管理页、数据库端口全都暴露在公网 IP 上，扫描器几分钟内就能找到。几件事必须做：token 用足够长的随机串；只映射确实要用的端口，不要图省事开一大片；管理类页面叠加一层访问鉴权；能用 IP 白名单（`allow_ips`）就只放自己的地址；对外的 Web 服务走 HTTPS。远程 SSH 建议改成证书登录、关掉密码登录。

验证是否成功，看三项：frps 日志无报错、frpc 日志出现 `start proxy success` 之类的提示、外部用 `公网IP:remotePort` 能打开内网服务的真实内容。三项都过，链路就是通的。连不通时按 token、端口、frpc 是否连上 frps 的顺序排查，不要一上来就改配置。

使用边界也说一句：frp 只应用于访问你自己拥有、用途合规的内网服务，不能拿来绕过网络管理或暴露未授权的系统。

## 自己搭还是买成品：三条路的门槛

**frp 自建**：门槛是要有一台公网服务器、会改配置文件、会放行端口。好处是端口、协议、域名全由自己控制，成本就是一台最低配机器的钱，长期跑下来最便宜。

**自托管面板（如 Nexo 联巢）**：把穿透做成了可视化管理，支持 TCP、UDP、HTTP、HTTPS，域名证书通过 Caddy 自动申请续期，Agent 用 mTLS 通道连接。门槛在部署：官方镜像只支持 Linux/amd64，需要 Docker Engine 和 Docker Compose v2，服务端必须公网可达，同机反向代理和内置 Caddy 不能同时占用 80/443。版本上有硬限制，v0.2.4 及更早版本不支持原地升级，得用独立空数据目录重装。适合有 Docker 基础、又不想手写配置的人。

**商业穿透服务（如花生壳）**：不用公网 IP、不用碰路由器，装客户端就能用，TCP 映射可以走远程桌面 3389、SSH 22、MySQL 3306。代价是免费版有流量限制，高流量场景要付费，端口和协议的可控性也不如自建。

三条路没有绝对优劣。只想让自己一个人从外面连回家，frp 加一台 18 元的机器是最省钱的组合；要给团队几个人分别开服务、还要管域名证书，面板类工具省事；完全不想碰命令行，成品服务更直接。
